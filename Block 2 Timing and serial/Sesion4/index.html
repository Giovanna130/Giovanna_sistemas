    Session 4 — Timers

    Goal: Measure and analyze the signals generated by a timer, using an oscilloscope, comparing the theoretical and experimental values ​​of the period, frequency, and duty cycle when modifying the switching interval of the signal.

    Prediction: It is expected that a square wave signal generated by the Raspberry Pi Pico will be observed on the oscilloscope, whose high and low state times will decrease as the timer interval is reduced, allowing the theoretical values ​​to be compared with the experimental measurements.

    Set Up

    To perform this experiment, the Raspberry was programmed to generate a square wave signal using a timer that changed the state of pin GP15 every 250 ms. An oscilloscope was then connected to observe and measure the signal, identifying the high and low states, the period, the frequency, and the duty cycle.

    Part A — Predict first, measure second

    What I did

    We calculate the theoretical signal values ​​before using the oscilloscope and then measure the actual signal to compare the results.

    Quantity Predicted Measured Difference
    Toggle interval 250 ms 249.8 ms 0.2 ms
    HIGH time 250 ms 249.8 ms 0.2 ms
    LOW time 250 ms 249.8 ms 0.2 ms
    Period 500 ms 499.8 ms 0.2 ms
    Frequency 2 Hz 2 Hz -
    Duty cycle 50% 50% -

    Evidence

    Code

    #include "pico/stdlib.h"
#include "pico/time.h"

#define TEST_PIN   15
#define TOGGLE_MS  250

static repeating_timer_t timer;

static bool timer_callback(repeating_timer_t *rt) {
    static bool state = false;

    state = !state;
    gpio_put(TEST_PIN, state);

    return true;
}

    Part B — Change only one variable

    What I did

    We modified only the TOGGLE_MS value in the program, changing it from 250 ms to 100 ms, 50 ms, and 10 ms. Before running the code in each configuration, I calculated the expected signal frequency and then used the oscilloscope to measure and observe the changes in the waveform.

    Code

    int main() {
    gpio_init(TEST_PIN);
    gpio_set_dir(TEST_PIN, GPIO_OUT);
    gpio_put(TEST_PIN, 0);

    add_repeating_timer_ms(-TOGGLE_MS, timer_callback, NULL, &timer);

    while (true) {
        // main() remains available for other work.
        tight_loop_contents();
    }
}

    Disclosure

    1. Does TOGGLE_MS represent the waveform period? No, it represents the time between every status update

    2. What mathematical relationship connects TOGGLE_MS and the measured signal frequency? T = 2 × TOGGLE_MS and f = T/1

    3. Does changing TOGGLE_MS change the duty cycle? Why? No, it's still 50% because the time in Low and High is the same.

    4. At what point does observing the signal with an LED become less useful than observing it with an oscilloscope? When the signal changes too fast for us to notice the LED blinking.

    Part C — Can the callback duration change the timing?

    What I did

    We used two pins to observe with the oscilloscope how the duration of an interrupt function affects the timing of a signal. I performed four experiments modifying the duration of the work within the function (WORK_US) and the timer type (USE_NEGATIVE_DELAY).

    Code

    #include "pico/stdlib.h"
#include "pico/time.h"

#define TEST_PIN            15
#define CALLBACK_MARK_PIN   14
#define TIMER_DELAY_MS      100
#define WORK_US             20000
#define USE_NEGATIVE_DELAY  1

static repeating_timer_t timer;

static bool timer_callback(repeating_timer_t *rt) {
    static bool state = false;

    gpio_put(CALLBACK_MARK_PIN, 1);

    state = !state;
    gpio_put(TEST_PIN, state);

    // Intentional workload for the experiment.
    busy_wait_us_32(WORK_US);

    gpio_put(CALLBACK_MARK_PIN, 0);
    return true;
}

int main() {
    gpio_init(TEST_PIN);
    gpio_set_dir(TEST_PIN, GPIO_OUT);

    gpio_init(CALLBACK_MARK_PIN);
    gpio_set_dir(CALLBACK_MARK_PIN, GPIO_OUT);

    int32_t delay_ms = USE_NEGATIVE_DELAY ? -TIMER_DELAY_MS : TIMER_DELAY_MS;
    add_repeating_timer_ms(delay_ms, timer_callback, NULL, &timer);

    while (true) {
        tight_loop_contents();
    }

    Disclosure

    1. What does the width of the CH2 pulse represent? It represents the time that takes to execute the callback.

    2. What changes when the repeating-timer delay changes from negative to positive? With negative (-100 ms), the next callback is scheduled based on the start of the callback. With positive (+100 ms), the 100 ms start counting after the callback ends.

    3. Why should callbacks and ISRs normally be short? Because while they run, they use the CPU and can delay other tasks or events.

    4. What do you expect if the callback takes longer than the requested interval? The callback can take almost all the available time and events might get delayed or not run exactly at the requested interval.

    5. Does a longer callback necessarily change the HIGH/LOW duty cycle of CH1? Explain from the measured edges rather than from the source code alone. Not necessarily, you have to check it on the oscilloscope. If the HIGH and LOW changes still have roughly the same duration, the duty cycle will stay around 50%. The important thing is to measure the edges of CH1, not just assume it from the code.

    What went wrong

    • Although nothing went wrong, the practice could be improved by taking several measurements to obtain more accurate results and comparing the theoretical values ​​with the experimental ones to identify possible variations in the signal.
